# ADR 0004: HTML5 Canvas 2D 渲染

## 状态

已接受

## 背景

项目需要渲染生物（黑色圆形头部、白色大眼睛、摆动尾巴）在屏幕上移动。
需要选择渲染技术：HTML5 Canvas 2D vs WebGL vs DOM/CSS。

## 决策

使用 **HTML5 Canvas 2D** 作为渲染方案。

## 考虑过的替代方案

### 替代方案1: WebGL / WebGPU
使用 WebGL 或 WebGPU 进行硬件加速渲染。

**拒绝原因**：
- 项目复杂度低，不需要 GPU 加速
- WebGL 代码复杂度高，增加维护成本
- Canvas 2D 在移动设备上性能已足够（单生物/少量生物）
- 需要处理着色器兼容性

### 替代方案2: DOM/CSS 动画
使用 div + CSS transform/animation 实现生物移动。

**拒绝原因**：
- 生物的尾巴摆动需要复杂的路径计算，CSS 难以实现
- 大量 DOM 元素影响性能（游戏模式多生物时）
- 粒子效果难以用 CSS 实现

### 替代方案3: 使用游戏引擎（Phaser/PixiJS）
引入成熟的游戏引擎。

**拒绝原因**：
- 项目规模小，引擎引入增加 100KB+ 体积
- 学习成本和依赖风险
- 核心需求简单，不需要引擎的高级功能

## 后果

### 正面
- 零依赖，浏览器原生支持
- 代码量可控，完全掌握渲染逻辑
- 文件体积小，加载快
- 跨平台兼容性好

### 负面
- 需要手动实现动画循环（requestAnimationFrame）
- 没有内置的碰撞检测、场景管理等
- 复杂特效需要更多代码

## 性能考量

| 场景 | 生物数量 | Canvas 2D 性能 |
|------|---------|---------------|
| 游戏模式 | 3-4个 | 流畅（60fps） |
| 动画模式 | 1个 | 流畅（60fps） |
| 粒子效果 | <20个 | 流畅（60fps） |
