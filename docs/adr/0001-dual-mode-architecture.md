# ADR 0001: 双模式架构（游戏模式 + 动画模式）

## 状态

已接受

## 背景

项目源于一个B站猫咪动画视频，需求存在两个完全不同的使用场景：
1. **互动场景** - 猫咪拍打屏幕捕捉移动的生物
2. **观赏场景** - 猫咪被动观看生物移动的动画

这两个场景的目标用户都是猫咪，但交互方式完全不同。

## 决策

采用**双模式架构**，将游戏模式和动画模式作为两个独立的运行时模式：

- **游戏模式** (Game Mode): 计时得分，多生物同时出现，支持点击交互
- **动画模式** (Animation Mode): 单生物循环，无得分，禁用交互，专注观赏

## 考虑过的替代方案

### 替代方案1: 单一游戏模式，添加"观赏开关"
在现有游戏模式中添加一个"观赏模式"开关，关闭得分和计时。

**拒绝原因**：
- 游戏模式的核心是"捕捉"，观赏模式的核心是"自然移动"
- 生物行为逻辑差异大（游戏模式生物快速随机移动，动画模式生物有停顿和路径规划）
- 混合会导致代码复杂度和认知负担增加

### 替代方案2: 完全独立的两个应用
将游戏和动画拆分为两个独立的HTML文件或应用。

**拒绝原因**：
- 共享大量代码（生物渲染、Canvas管理、音频系统）
- 用户需要在两个应用间切换，体验割裂
- 维护成本翻倍

## 后果

### 正面
- 两种模式可以独立优化，不互相影响
- 代码清晰，每种模式有明确的生命周期和状态管理
- 用户意图明确，启动时即确定使用场景

### 负面
- 需要维护两套生物行为逻辑（Creature vs AnimationCreature）
- 模式切换时需要清理状态
- 包体积略大于单一模式
